# Security Policy

## Architecture & privacy model

MusicLab is a local-first musical instrument:

- **No accounts, telemetry or external network calls.** Runtime composition, playback, saving and WAV export make zero third-party requests. Hosted deployments enforce `connect-src 'self'`.
- **Audio and microphone require explicit user gestures.** Sound never autoplays before interaction, master output is hard-limited to `−3 dBFS`, Escape / **Stop sound** silences playback immediately, and the optional **Hum** recorder accesses the microphone only when explicitly pressed.
- **Local Python server (`app.py`, `src/app_shell/server.py`, `src/song_store/store.py`):**
  - Binds strictly to loopback (`127.0.0.1`).
  - Rejects non-loopback `Host` headers (DNS-rebinding protection) and cross-origin `POST` requests (`Origin` must match the local `Host:port`, `Origin: null` is rejected, `Content-Type: application/json` is required, and request bodies are capped at `5 MiB`).
  - Blocks directory traversal on static files and exported WAV downloads, restricts song IDs to `[A-Za-z0-9_-]{1,120}` (blocking Windows reserved device names and case-folding collisions), and writes song files atomically.
- **Bounded file import & asset verification:**
  - `.musiclab.json` validation (`static/js/project_validation.js`) enforces a `5 MiB` byte limit, `16,384` maximum notes, `64` maximum object nesting depth, finite numeric bounds, and `Object.prototype` key guards.
  - MusicXML import (`static/js/theory/score_sheet.js`) strips `<!DOCTYPE ...>` and processing instructions without invoking `DOMParser` or external entity resolution.
  - Sampled sound-bank loading (`static/js/audio/sampled_bank_delivery.js`) verifies exact byte length and SHA-256 via Web Crypto before passing bytes to the synthesizer.
  - `MANIFEST.json` records SHA-256 hashes for every file in the release tree.

## Safe deployment & untrusted song files

- **Open untrusted `.musiclab.json` files in the default `PlayFlow` interface** (`/static/index.html`), which HTML-escapes song metadata and note labels. Avoid opening untrusted third-party `.musiclab.json` files in the legacy `?studio=1` debug view.
- **When self-hosting publicly**, serve static assets with `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, and the hash-pinned `Content-Security-Policy` generated by `hosting/stage-musiclab-cloudflare.mjs` (`default-src 'self'; connect-src 'self'; object-src 'none'`). Do not expose `python app.py` directly on a public network interface; use static hosting for multi-user web deployments.

## Reporting a vulnerability

Please do **not** post exploitable security vulnerabilities in public GitHub issues.

Report security issues privately via **GitHub Security Advisories** in this repository's **Security → Report a vulnerability** tab.

Include steps to reproduce, whether the issue affects static browser mode or `python app.py` local server mode, and the commit hash from `MANIFEST.json`.
